# BSL Pitfalls — грабли языка 1С (наблюдения из практики)

При написании или проверке BSL-кода для этого проекта. Каждый пункт — реальная ошибка,
встреченная при загрузке конфигурации в 1С. Проверять код по этому списку **до** загрузки.

## Синтаксис: конструкций, которых НЕТ в BSL

| Не существует | Вместо этого |
|---|---|
| `Выбрать X … Когда "a" … КонецВыбора` (switch) | `Если X = "a" Тогда … ИначеЕсли X = "b" Тогда … Иначе … КонецЕсли;` |
| `Для i = N По -1 До 0 Цикл` (отрицательный шаг) | `i = N; Пока i >= 0 Цикл … i = i - 1; КонецЦикла;` |
| `Новый Массив(Эл1, Эл2)` (конструктор с аргументами) | `М = Новый Массив; М.Добавить(Эл1); М.Добавить(Эл2);` |
| `РазделитьСтроку(Строка, Разделитель)` | `СтрРазделить(Строка, Разделитель)` — встроенная функция (8.3.17+), возвращает Массив строк |
| `Переменная Имя;` на уровне модуля (в начале общего/формы-модуля) | В **общих** модулях переменные не объявляются вообще: любое имя становится переменной модуля при первом присваивании в теле модуля. Оператор `Переменная` существует только для **локальных** переменных внутри процедур и функций. Грабли из практики: я (LLM) сам сгенерировал такое объявление в общем модуле — проверять чужой/свой код по этому списку до загрузки |
| `Новый Интервал(0, 7, 0, 0)` (конструктор Interval) | Конструктора нет: «Тип не определен (Интервал)» при компиляции. Тип `Интервал` — только результат арифметики дат. Прибавить часы/минуты к дате — `ДобавитьКДате(ТекущееВремя(), 7, Час)`; дни — `Дата + Число`; сравнить интервал с числом — `(Разница - Число) > 0` |

## Синтаксис: конструкции, которые ЛЕГКО сломать

- **`Окно` — не имя для локальной переменной в модуле формы.** Платформа видит
  в нём свойство формы/клиентского контекста (только для чтения) и выдаёт
  «Поле объекта недоступно для записи (Окно)» на первом же присваивании.
  В общих модулях `Окно = ...` компилируется, а в форме — нет: называйте
  `ОкноСтраницы`, `ОкноФормы`, `ОкноБраузера`. То же правило для имён,
  совпадающих с `Элементы`, `ЭтаФорма`, `РеквизитФормы`, `Параметры`.

- **`Попытка … Исключение … КонецПопытки`** — всегда три части, и блок `Исключение`
  **не может быть пустым** (минимум одно действие: комментарий, присваивание, `Возврат`).
  
  ```bsl
  // НЕДОПУСТИМО — пустой Исключение:
  Попытка
      ...
  Исключение
  КонецПопытки;
  
  // ДОПУСТИМО:
  Попытка
      ...
  Исключение
      // Игнорируем ошибку.
  КонецПопытки;
  ```
  
  Если парсер говорит «Ожидается ключевое слово 'Исключение'» на `КонецПопытки` —
  либо `Исключение` отсутствует, либо блок пустой. Искать **выше** по стеку блоков.

- **`#Область … #КонецОбласти`** — каждый `#Область` обязан иметь `#КонецОбласти`.
  Вложенные области разрешены, но счётчик должен сходиться. Проверка:
  `grep -c '#Область' file` == `grep -c '#КонецОбласти' file`.
  
  **Важно:** при вставке нового `#Область` внутри существующего — сначала закрыть
  внешний (`#КонецОбласти`), потом открыть новый. Иначе парсер BSL теряет позицию
  и даёт каскадную ошибку на `КонецПопытки`/`КонецЕсли` далеко от места проблемы
  (ошибка «Ожидается ключевое слово 'Исключение'» может указывать на строку,
  которая сама по себе корректна).

- **`НСтр("ru = 'текст с переводом строки'")`** — литерал не может содержать
  реальный перевод строки. Использовать `Символы.ПС` или конкатенацию.

- **`ТаблицаЗначений.Найти(Значение, Колонки)` в живой базе падала
  «Метод объекта не обнаружен (Найти)»**, хотя метод есть в справке с 8.0
  (форма V3-чата, реквизит формы типа `v8:ValueTable`). Не рискуйте: ищите
  строку обходом `Для Каждого Строка Из Таблица Цикл … Возврат Строка;`.
  Заодно не зовите `Таблица.Индекс(Строка)` — сразу после `Таблица.Добавить()`
  последняя строка и так `Таблица.Количество() - 1`.

## Форматирование дат и чисел — функция `Формат()`

Синтаксис: `Формат(<Значение>, <ФорматнаяСтрока>)`. Два типа форматных строк:
`"ДФ='...'"` — дата/время, `"ПФ='...'"` — число.

### Спецификаторы даты (`ДФ`)

| Спецификатор | Значение | Пример |
|---|---|---|
| `ДД` / `D` | День месяца (2-значный / авто) | `01`, `31` |
| `ММ` / `M` | Месяц (2-значный / авто) | `01`, `12` |
| `МММ` / `ММММ` | Краткое / полное название месяца | `янв` / `январь` |
| `ГГГГ` / `ГГ` | Год (4-значный / 2-значный) | `2026`, `26` |
| `ЧЧ` / `чч` | Часы 24ч / 12ч | `09`, `23` |
| `мм` | Минуты (нижний регистр!) | `05`, `59` |
| `СС` | Секунды | `00`, `45` |

### Спецификаторы числа (`ПФ`)

| Спецификатор | Значение |
|---|---|
| `ЧДЦ=-1` / `ЧДЦ=N` | Цифр целой части: авто / фиксированно N |
| `ЧРЧ=N` | Знаков после запятой (по умолчанию 2) |
| `ЧРазделитель=Да/Нет` | Разделитель тысяч |

### Примеры

```bsl
// Дата + время (проверено в конфигураторе):
Формат(ТекущаяДата(), "ДФ=""дд.ММ ЧЧ:мм""")         // → "31.10 15:45"
Формат(Дата, "ДФ='ДД.ММ.ГГГГ ЧЧ:МИ:СС'")           // → "31.10.2026 15:45:30"
Формат(Дата, "ДФ='ДД ММММ ГГГГ г.'")               // → "31 октября 2026 г."

// ВНИМАНИЕ: минуты — это `мм` (нижний регистр), НЕ `МИ` и НЕ `ММ`.
// `ММ` = месяцы. Ошибка ДФ='ДД.ММ ЧЧ:ММ' выводит месяц вместо минут.

// Число:
Формат(Сумма, "ПФ='ЧДЦ=-1; ЧРЧ=2; ЧРазделитель=Да'")  // → "1 234,57"
Формат(Сумма, "ПФ='ЧДЦ=-1; ЧРЧ=0'")                   // → "1 235"

// ОСТОРОЖНО: "ЧЦ=0" — это НЕ «ноль знаков», а число знаков целой части.
// Оно включает разделитель разрядов: Формат(4041, "ЧЦ=0") → "4 041".
// Для целого без разделителя: Формат(Число, "ЧДЦ=0; ЧРазделитель=Нет").

// НЕПРАВИЛЬНО — Число вместо ДатаВремя:
Формат(ТекущаяУниверсальнаяДатаВМиллисекундах() / 1000, "ДФ='ДД.ММ ЧЧ:МИ'")
// ТекущаяУниверсальнаяДатаВМиллисекундах() → Число (мс). ДФ для числа не работает.
```

**Правило:** в `Формат` с `ДФ` передавать только значения типа `Дата`.
Для мс-эпохи: сначала преобразовать (`Дата(Число)` или через `УниверсальноеВремя`).

## Модули формы: доступ к атрибутам

| Тег | Доступ к атрибутам формы | Когда использовать |
|---|---|---|
| `&НаКлиенте` | Да (читает/пишет) | Обработчики команд, UI-логика |
| `&НаСервере` | Да (читает/пишет) | Серверная логика, HTTP-вызовы |
| `&НаСервереБезКонтекста` | **НЕТ** | Чистые функции без обращения к форме |

### Переменные модуля формы — обязательна директива компиляции

В модуле управляемой формы `Перем` **без директивы платформа не видит**:
модуль загружается, но каждый вызов даёт «Переменная не определена» и
«Ошибка инициализации модуля» (BSL LS это НЕ ловит — проверяйте глазами).

```bsl
&НаКлиенте
Перем ОжиданиеХода;            // клиентская переменная
&НаСервере
Перем КэшПоследнегоОтвета;     // серверная переменная (своя копия)

#Область ОбработчикиСобытийФормы
...
```

- У клиента и сервера **свои экземпляры** переменных: значение, выставленное
  на клиенте, на сервере не видно — передавайте параметрами.
- `&НаСервереБезКонтекста`-переменные недоступны и в контексте формы.
- **Начального значения у переменной нет** — до первого присваивания это
  `Неопределено`. `Перем X = Ложь;` в 1С недопустим, а `Если X Тогда` при
  `Неопределено` падает с «Преобразование значения к типу Булево не может быть
  выполнено». Инициализировать в `ПриОткрытии` (клиентские) или
  `ПриСозданииНаСервере` (серверные). Для `ПриОткрытии` нужен обработчик
  `OnOpen` в Form.xml (`<Event name="OnOpen">ПриОткрытии</Event>`).

Если функция в `&НаСервереБезКонтекста` обращается к атрибуту формы (например
`АдресБэкенда`) — ошибка «Переменная не определена». Либо менять на `&НаСервере`,
либо передавать значение параметром.

## Серверные функции, которые НЕЛЬЗЯ вызывать из `&НаКлиенте`

Ошибки «Процедура или функция с указанным именем не определена» /
«Переменная не определена» на серверных объектах — признак вызова серверного API
из клиентского кода. Полный список:

| Серверный объект/функция | Что делать |
|---|---|
| `ЗаписьЖурналаРегистрации(...)` | Вынести в `&НаСервере` хелпер, вызвать из клиента |
| `УровеньЖурналаРегистрации.Ошибка` (и другие значения перечисления) | Только на сервере |
| Общий модуль с `&НаСервере` (например `a1c_ЧатOpenCodeФоновый`) | Вынести вызов в `&НаСервере` функцию формы |
| `Запрос`, `СообщениеПользователюСВозможностьюОтказа` и др. серверные встроенные | Аналогично — хелпер на сервере |

**Паттерн:**
```bsl
// Клиент:
&НаКлиенте
Процедура Обработчик(Команда)
    Попытка
        ...
    Исключение
        ЗаписатьОшибкуНаСервере(ПодробноеПредставлениеОшибки(ИнформацияОбОшибке()));
    КонецПопытки;
КонецПроцедуры

// Сервер (в том же модуле формы):
&НаСервере
Процедура ЗаписатьОшибкуНаСервере(Знач Текст)
    ЗаписьЖурналаРегистрации("ИИ-чат", УровеньЖурналаРегистрации.Ошибка, , , Текст);
КонецПроцедуры
```

Атрибуты формы передаются на сервер автоматически при вызове `&НаСервере` функции
из клиента (формат «клиент → сервер» управляемых форм).

## Клиентские функции, которые НЕЛЬЗЯ вызывать из `&НаСервере`

Обратная ситуация: клиентский API в серверном коде. Ошибка «Процедура или функция
с указанным именем не определена».

| Клиентская функция | Что делать |
|---|---|
| `УстановитьВнешнююКомпоненту(...)` | Вынести в `&НаКлиенте` процедуру, вызвать до серверного кода |
| `НачатьУстановкуВнешнейКомпоненты(...)` | Только на клиенте (8.3.16+) |
| `ПодключитьВнешнююКомпоненту(...)` | Только на клиенте |
| `ПоказатьПредупреждение(...)`, `Сообщить(...)` | Вынести в `&НаКлиенте` или использовать серверные аналоги |

**Паттерн установки внешней компоненты (тонкий клиент):**

В тонком клиенте **нет функции Sleep/Ожидание** для синхронной задержки.
`НачатьУстановкуВнешнейКомпоненты` — асинхронная операция, нужно использовать
`ОписаниеОповещения` для получения уведомления о завершении установки.

```bsl
// Клиент — установка из макета (асинхронно с оповещением):
&НаКлиенте
Процедура УстановитьКомпонентуWS()
    ИмяМакета = "Обработка.Имя.Макет.WebTransportAddIn";
    
    Попытка
        // Сначала пытаемся подключить — если уже установлена, сразу подключаем.
        Если ПодключитьВнешнююКомпоненту(ИмяМакета, "WebTransport") Тогда
            Возврат;
        КонецЕсли;
    Исключение
    КонецПопытки;

    // Компонента не установлена — начинаем асинхронную установку с оповещением.
    НачатьУстановкуВнешнейКомпоненты(
        Новый ОписаниеОповещения("WS_КомпонентаУстановлена", ЭтотОбъект),
        ИмяМакета);
КонецПроцедуры

// Клиент — обработчик завершения установки:
&НаКлиенте
Процедура WS_КомпонентаУстановлена() Экспорт
    ИмяМакета = "Обработка.Имя.Макет.WebTransportAddIn";
    
    Попытка
        ПодключитьВнешнююКомпоненту(ИмяМакета, "WebTransport");
        // После установки — подключаемся к WS-мосту на сервере.
        ПодключитьсяКСобытиям();
    Исключение
    КонецПопытки;
КонецПроцедуры

// Клиент — обработчик открытия формы:
&НаКлиенте
Процедура ПриОткрытии(Отказ)
    УстановитьКомпонентуWS();
КонецПроцедуры

// Сервер — подключение (вызывается из WS_КомпонентаУстановлена или сразу):
&НаСервере
Процедура ПодключитьсяКСобытиям()
    Попытка
        Объект = Новый("AddIn.WebTransport.ws");
        ...
    Исключение
    КонецПопытки;
КонецПроцедуры

// Сервер — обработчик создания формы:
&НаСервере
Процедура ПриСозданииНаСервере(Отказ, СтандартнаяОбработка)
    // Пытаемся подключить сразу (если компонента уже установлена).
    Попытка
        Новый("AddIn.WebTransport.ws");
        ПодключитьсяКСобытиям();
    Исключение
        // Не установилась — ждём установки (ПриОткрытии → WS_КомпонентаУстановлена).
    КонецПопытки;
КонецПроцедуры
```

**Важно:** 
- `УстановитьВнешнююКомпоненту` устарела с 8.3.16 — использовать
  `НачатьУстановкуВнешнейКомпоненты(ОписаниеОповещения, Местоположение)`.
- **Клиентские функции нельзя вызывать из серверных обработчиков** 
  (`ПриСозданииНаСервере`, `&НаСервере` процедуры). Установка компоненты —
  в `ПриОткрытии` (клиентский контекст), подключение — в `ПриСозданииНаСервере`.
- **Нет Sleep/Ожидание на клиенте** — для асинхронных операций использовать
  `ОписаниеОповещения`, не циклы с задержкой.

## Асинхронный ход в форме без внешних компонент (опрос вместо WS)

Пуш-событий в открытую управляемую форму из 1С-кода нет: внешняя компонента
(WS) — лишняя точка отказа, и её установка тянет за собой макет, платформенные
ограничения тонкого клиента и отдельный мост на сервере. Рабочая схема —
**опрос состояния по таймеру**:

```bsl
// Клиент: запуск опроса
ПодключитьОбработчикОжидания("ОбработчикОпросаХода", 0.5, Истина);

&НаКлиенте
Процедура ОбработчикОпросаХода()
    Если Не ОжиданиеХода Тогда
        Возврат;                                  // не перевзводим таймер
    КонецЕсли;
    Состояние = ОбновитьХодНаСервере(ВремяНачалаХода);   // один шаг опроса
    Если Состояние.Завершено Тогда
        ОстановитьОпроса();
        Возврат;
    КонецЕсли;
    ПодключитьОбработчикОжидания("ОбработчикОпросаХода", 0.5, Истина);
КонецПроцедуры
```

Правила:

- Интервал **меньше 1 секунды допустим только с `Однократно = Истина`** —
  иначе платформа молча игнорирует или ругается. Поэтому `0.5, Истина`
  и обязательный перевзвод таймера в конце обработчика.
- `ОжиданиеХода`, `ВремяНачалаХода`, `НачалоОпроса` — **переменные модуля
  формы** (`Перем` до первой области), а не реквизиты. У клиента и сервера
  они свои, поэтому на сервер их передают **параметрами**. Form.xml при этом
  править не нужно.
- Каждый шаг опроса — синхронный серверный вызов: в нём не должно быть
  циклов ожидания. `Пока Истина … ПолучитьСообщение()`/`HTTPСоединение`
  с большим таймаутом вешает форму: короткий таймаут (10–15 с) + возврат
  состояния.
- Страховка от вечного опроса: локальное время старта и порог (10 минут),
  после которого опрос останавливается и кнопка отправки разблокируется.
- `ПередЗакрытием` обязан вызывать `ОстановитьОпроса()` (`ОтключитьОбработчикОжидания`).
- Свойства элементов формы, изменённые **только на клиенте**, при следующем
  серверном вызове возвращаются с сервера. Если группа/поле прячется на
  клиенте, спрятать её надо и в `&НаСервере` процедуре, иначе она «всплывёт».

## Поле HTML-документа: страница как интерфейс (V3-чат)

Схема: страница рисуется **один раз** присваиванием
`Элементы.ПанельHTML = СформироватьСтраницу(...)`, дальше 1С только зовёт её
JS-функции (`upsertMessage`, `setMeta`, `showQuestion`, `setStatus`, `setBusy`).
Обратно — клики по ссылкам `#act:...`. Так не сбрасывается прокрутка и не
перерисовываются уже показанные сообщения.

- **События в Form.xml** называются по-английски: `OnClick` (обработчик
  `ПриНажатии(Элемент, ДанныеСобытия, СтандартнаяОбработка)`) и
  `DocumentComplete` (`ДокументСформирован(Элемент)`). Параметр `Элемент`
  платформа передаёт всем обработчикам элементов формы — в типовых
  конфигурациях подпись именно `(Элемент)`, без него обработчик не вызовется.
- **`ДанныеСобытия.Href` — абсолютный URL, а не `#act:send`.** Движок
  подставляет базу документа (`about:blank#act:send`, `file:///...#act:send`),
  поэтому сравнивать целиком нельзя — только `СтрНайти(Href, "#act:")` и брать
  хвост. `ДанныеСобытия.Anchor` заполнен лишь при клике по `<a>`, при клике
  мимо ссылки `Href = Неопределено`. В `href` лучше класть латиницу
  и индексы (`#act:opt|0|1`), а не текст: кириллица в URL кодируется.
- **`СтандартнаяОбработка = Ложь` обязательна**, иначе поле перейдёт по якорю
  и страница «прыгнет» (в лучшем случае — прокрутится к элементу).
- **`ДокументСформирован` приходит не всегда** (в веб-клиенте и тонком под
  Windows — по-разному, повторная отрисовка того же текста события не даёт).
  Нужен сторож: раз в секунду (однократный таймер + перевзвод) проверять
  `Элементы.ПанельHTML.Документ.getElementById("prompt") <> Неопределено`
  и только тогда ставить `СтраницаГотова = Истина`; после 30 попыток бросить.
  `getElementById` вызывается у **документа**, не у окна.
- **Окно документа:** в веб-клиенте и клиенте на WebKit — `Документ.defaultView`,
  в тонком клиенте под Windows (движок IE) — `Документ.parentWindow`. Каждое
  обращение — в `Попытка`: отсутствующее свойство COM-объекта даёт исключение,
  а не `Неопределено`. Одна функция `ПолучитьОкноСтраницы()` на всё.
- **Текст из DOM** читается как `Окно.document.getElementById('prompt').value`;
  если окно не получено — fallback на `ПоказатьВводСтроки`, иначе промпт молча
  теряется.
- **Не останавливать опрос, если вопрос уже отвечен.** Сервер может ещё
  возвращать форму, пока обрабатывает ответ; остановка опроса подвесит ход до
  таймаута. Запоминать `ОтвеченныйИдВопроса` и продолжать опрос, не показывая
  карточку повторно (отдельная переменная от «карточка сейчас на странице»).
- **Полная перерисовка — только аварийный fallback** (исключение при вызове JS):
  присваивание поля перезагружает документ. После неё восстанавливать статус,
  занятость и карточку вопроса из переменных модуля — страница их не помнит.
- **В JS не хранить состояние**: все id и тексты приходят из 1С. Перезагрузка
  документа (перерисовка, смена движка) состояние JS обнуляет.
- `innerHTML` с ведущим переводом строки/пробелами даёт `firstChild` —
  текстовый узел. Перед разбором: `html.replace(/^\s+/, '')`.
- **Кириллицу держать в BSL, а не в макетах** `Template.txt`: макеты читаются
  как есть (исторически cp1251), модуль — UTF-8; русские подписи, собранные
  в BSL и вставленные в страницу, кодировку не ломают. В макетах — только
  ASCII (CSS/JS/каркас с `{{STYLES}}`/`{{SCRIPT}}`/`{{HEADER}}`).

## API сервера OpenCode: что проверено живыми запросами

| Запрос | Что отдаёт / грабли |
|---|---|
| `POST /api/session/{sid}/prompt` | Квитанция `data.time.created` — **время начала хода**, по нему фильтруются сообщения хода |
| `GET /api/session/{sid}/message?order=desc&limit=50` | Сообщения: `user`, `assistant` (`content[].type = text/reasoning/tool`), `idle` (`outcome = succeeded/failed/interrupted`) |
| `GET /api/session/{sid}/form` | Ожидающие формы-вопросы: `data[].id`, `title` (обычно `Questions` — не показывать), `fields[].key/title/description/options[]` |
| `POST /api/session/{sid}/form/{fid}/reply` | Тело `{"answer":{"q0":"текст"}}`, ответ **204**. После reply форма исчезает, ход продолжается. Если у формы несколько полей (`q0`, `q1`, …), ответить нужно **всем** ключам — иначе форма остаётся pending и ход не идёт дальше |
| `GET /api/provider` | **НЕТ поля `models`** (только `id/settings`) — список моделей в `GET /api/model` (`providerID`, `modelID`), дефолт — `GET /api/model/default` |
| `GET /api/agent` | `mode` (`primary`/`subagent`) + `hidden` — для дропдауна годятся только `primary` и не `hidden` |

- Ход считается завершённым по сообщению `idle` с `time.created >= ВремяНачала`,
  и только если нет ожидающих форм: пока форма не отвечена, `idle` не появляется.
- **У формы может быть несколько полей (`q0`, `q1`, …) — у каждого свой ответ.**
  Нельзя отвечать первым выбранным текстом на все ключи: пользователь должен
  выбрать/ввести ответ по каждому полю, а `reply` уходит один, со всеми ключами.
  В UI вариант — только подсветка и запоминание, отправка — отдельной кнопкой
  (иначе второй вопрос выбрать не успевает). Если хотя бы одно поле пустое,
  `reply` не отправлять: форма останется pending, ход зависнет.
- Сессии **не переживают рестарт сервера** (404) — при 404 создавать новую сессию.
- В `/api/provider` нет `models` → сессия уходит на дефолтную модель сервера
  (`flint-40b-free`), а не на qwen; это не ошибка кода формы.

## XDTO / Form.xml: элементы, которые платформа НЕ принимает

- `<Group>AlwaysVertical</Group>` внутри `<UsualGroup>` — **не поддерживается**
  (ошибка «Несоответствие свойства и элемента данных XDTO: Свойство Group»).
  Вертикальная компоновка — поведение по умолчанию для вложенных групп.
  Допустимые значения `<Group>` только для верхнего уровня формы или
  при определённых версиях платформы; в UsualGroup внутри ChildItems — не использовать.

## Структура XML-исходников обработки

```
DataProcessors/
├── a1c_ИмяОбработки.xml          ← файл объекта (рядом с папкой, НЕ внутри)
└── a1c_ИмяОбработки/
    ├── Forms/Форма.xml
    ├── Forms/Форма/Ext/Form.xml
    ├── Forms/Форма/Ext/Form/Module.bsl
    └── Templates/ШаблонДиалога.xml
```

Файл объекта `<Имя>.xml` лежит **на уровне DataProcessors/**, а не внутри папки.
Иначе: «Файл объекта не существует».

- **Теги пространства `v8` обязаны быть с префиксом.** `<content>Текст</content>`
  вместо `<v8:content>` платформа читает как свойство `content` в пространстве
  MDClasses и падает на загрузке: «Ошибка XDTO в файле — Форма.xml, при чтении
  свойства: content… Тип LocalStringType». То же для `<lang>`,
  `<Value>`, `xsi:type`. Проверка перед загрузкой:
  `grep -rn '<content>\|<lang>' --include=*.xml .` → пусто (кроме
  `v8:content`/`v8:lang`).

## Чек-лист перед загрузкой конфигурации

1. `grep -n 'Выбрать\|Когда \|КонецВыбора' Module.bsl` → пусто
2. `grep -n 'По -1\|По -[0-9]' Module.bsl` → пусто
3. Счётчики: Попытка/КонецПопытки, Для+Пока/КонецЦикла, Если/КонецЕсли, Функция/КонецФункции — равны
4. `#Область` == `#КонецОбласти` по количеству
5. `&НаСервереБезКонтекста` функции не обращаются к атрибутам формы
6. Form.xml: нет `<Group>` внутри UsualGroup (кроме верхнего уровня)
7. Файл объекта `.xml` на уровне DataProcessors/, не внутри папки
8. Все UUID в XML уникальны (не скопированы из другого объекта без замены)
9. `grep -n 'ЗаписьЖурналаРегистрации\|УровеньЖурналаРегистрации' Module.bsl` — каждая строка должна быть внутри `&НаСервере`/`&НаСервереБезКонтекста` процедуры (проверить по ближайшему тегу выше)
10. Вызовы серверных общих модулей (`a1c_ЧатOpenCodeФоновый.*`) — только из `&НаСервере` кода
11. `grep -n 'УстановитьВнешнююКомпоненту\|НачатьУстановкуВнешнейКомпоненты\|ПодключитьВнешнююКомпоненту' Module.bsl` — только в `&НаКлиенте` процедурах
12. `ПоказатьПредупреждение`, `Сообщить` — только в `&НаКлиенте` (или использовать серверные аналоги)
13. `ПодключитьОбработчикОжидания` с интервалом < 1 c — только с `Однократно = Истина` и перевзводом в конце обработчика
14. Свойства элементов формы (видимость/заголовок), меняемые на клиенте, продублированы на сервере в `&НаСервере` процедуре
15. Нет циклов ожидания на сервере (`Пока Истина … ПолучитьСообщение()`): HTTP-таймаут ≤ 15 c, состояние возвращается порциями
16. Поле HTML-документа: события `OnClick`/`DocumentComplete` подписаны, в `ПриНажатии` есть `СтандартнаяОбработка = Ложь`, `Href` ищется по подстроке `#act:` (он абсолютный URL)
17. `ДокументСформирован` продублирован сторожем по однократному таймеру с перевзводом; готовность — `Документ.getElementById("prompt") <> Неопределено`
18. Доступ к DOM — только через `ПолучитьОкноСтраницы()` (`defaultView`, затем `parentWindow`, каждое в `Попытка`); чтение `value` имеет fallback
19. Страница не перерисовывается на каждое сообщение — только вызовы JS; полная перерисовка лишь в `Исключение` и с восстановлением статуса/вопроса
20. `grep -rn '<content>\|<lang>' --include=*.xml .` → пусто: все теги пространства `v8` с префиксом (иначе ошибка XDTO при загрузке)
21. Нет локальных переменных с именами свойств формы/контекста (`Окно`, `Элементы`, `ЭтаФорма`, `Параметры`) — иначе «Поле объекта недоступно для записи»
22. `grep -n '\.Найти(\|\.Индекс(' Module.bsl` → пусто для `ТаблицаЗначений`: искать обходом строк, индекс — `Количество() - 1`

## Уровень доверия к BSL LS: «0 критичных» ≠ работает

BSL Language Server (`data/bsl-ls/bsl-language-server-*.jar`, `analyze -r json`)
— статический линтер. Он ловит синтаксис и часть структуры, но **не поведение
платформы**. На практике (V3) «0 критичных» он дал, а в базе всё равно упало:

- «Метод объекта не обнаружен (Найти)» — метод документирован, статически валиден.
- «Поле объекта недоступно для записи (Окно)» — присваивание законно, ограничение контекста формы.
- XDTO на `<content>` без `v8:` — это XML, BSL LS его не читает вообще.

Типовые ложные срабатывания, которые можно игнорировать: `InvalidCharacterInFile`
(длинное тире), `MissingCodeTryCatchEx` (в `Исключение` только комментарий),
`CognitiveComplexity`, `DuplicateStringLiteral`, `MagicNumber`, `Typo`,
`NonStandardRegion`, `LatinAndCyrillicSymbolInWord`, `CompareWithBoolean`,
`IfElseIfEndsWithElse`, `MissingReturnedValueDescription`, `CodeOutOfRegion`.

Порядок проверок и их слепые зоны — `agent/onec/TESTING.md`. BSL LS — гигиена,
не тест: «0 критичных» не означает «работает».
