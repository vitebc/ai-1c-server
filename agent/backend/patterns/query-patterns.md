# Шаблоны запросов 1С

Правила языка запросов (нарушение = синтаксическая ошибка 1С, не чинится повторами):

0. **Каждый запрос начинается с `ВЫБРАТЬ РАЗРЕШЕННЫЕ`** — иначе 1С вернёт строки,
   которые текущему пользователю не разрешили видеть (RLS/профили групп доступа).
   Бэкенд подставляет `РАЗРЕШЕННЫЕ` автоматически, но пиши его сам: так текст запроса
   в логах и в `validate_query` совпадает с тем, что реально выполняется.
   Верно: `ВЫБРАТЬ РАЗРЕШЕННЫЕ ПЕРВЫЕ 10 Поле ИЗ Таблица`.
   Ключевое слово `РАЗРЕШЕННЫЕ` доступно только у первого запроса.
1. Даты — ТОЛЬКО конструкцией `ДАТАВРЕМЯ(ГГГГ,М,Д)`. Фильтр за день:
   `Дата >= ДАТАВРЕМЯ(2026,9,18) И Дата < КОНЕЦПЕРИОДА(ДАТАВРЕМЯ(2026,9,18), ДЕНЬ)`.
   Запрещено: `ДАТА('20260918')`, `ДАТА(Дата, ...)`, сравнения даты со строками.
   Пустая дата (бессрочный договор) — `ДАТАВРЕМЯ(1,1,1)`.
2. Сначала `validate_query` (тот же текст с `ПЕРВЫЕ 1`), потом полный `execute_select`. Без успешной проверки полный запрос не запускать.
3. Подполя ссылок не выдумывать: `Контрагент.INN` в документе может не существовать. Смотри структуру документа И структуру справочника (`get_metadata_structure` для обоих), фильтр по ИНН — через справочник Контрагенты, затем отбор по ссылке.
4. Разведка метаданных — максимум 3 вызова, дальше пиши запрос.
5. Один запрос чинить максимум 2 раза. Третья ошибка подряд — остановиться: показать пользователю, что пробовал (текст запроса + текст ошибки 1С), и спросить уточнение.
6. В `ПОДОБНО` спецсимволы `%` и `_` экранируй как `[%]` и `[_]`; параметры `&` не поддерживаются — только литералы.
7. Контрагент — два шага, без повторного широкого поиска:
   1) ОДИН запрос к справочнику контрагентов с нечётким поиском:
      `ВЫБРАТЬ РАЗРЕШЕННЫЕ ПЕРВЫЕ 5 Ссылка, Наименование, ИНН, Код ИЗ Справочник.Контрагенты ГДЕ Наименование ПОДОБНО "%слово%"`
      (разбей фразу пользователя на слова). Точное совпадение по наименованию — это он;
      несколько кандидатов — покажи их пользователю и спроси, кого имел в виду.
   2) Дальше фильтр в документе — ТОЛЬКО через примитивные подполя ссылки:
      `ГДЕ Контрагент.ИНН = "<найдённый ИНН>"` (или `.Код`).
   ЗАПРЕЩЕНО: `ГДЕ Контрагент = "строка"` — строка в ссылочном поле не совпадает ни с чем,
   результат пустой БЕЗ ошибки; и повторный широкий поиск «на всякий случай».
8. `ПЕРВЫЕ` — ТОЛЬКО сразу после `ВЫБРАТЬ`, не после имени таблицы.
   Верно: `ВЫБРАТЬ ПЕРВЫЕ 10 Поле ИЗ Таблица`. Ошибка: `ВЫБРАТЬ Поле ИЗ Таблица ПЕРВЫЕ 10`.
9. Подсчёт строк — `СУММА(1) КАК КЗ`, а НЕ `СЧЁТЧИК`/`ПОДСЧИТАТЬ`:
   в проверенных базах `СЧЁТЧИК(*)` и `ПОДСЧИТАТЬ(1)` дают синтаксическую ошибку.
   Верно: `ВЫБРАТЬ СУММА(1) КАК КЗ ИЗ Таблица ГДЕ <отбор>`.
10. Группировка — `СГРУППИРОВАТЬ ПО`, буква «С» обязательна:
   `ВЫБРАТЬ Статус, СУММА(1) КАК КЗ ИЗ Таблица СГРУППИРОВАТЬ ПО Статус УПОРЯДОЧИТЬ ПО КЗ УБЫВ`.
   Без «С» — синтаксическая ошибка «ПО».
11. Незаполненное поле — `ГДЕ <Поле> ЕСТЬ NULL`. Конструкция `ЕСТЬ НЕОПРЕДЕЛЕНО`
   не поддерживается.
12. Поля-перечисления (`Статус`, `ТипДоговора` и подобные) НЕ фильтруются строкой:
   `ГДЕ Статус = "Действует"` вернёт пусто, а полное имя
   `Перечисления.СтатусыДоговоровКонтрагентов.Действует` — «Поле не найдено».
   Единственный рабочий способ узнать фактические значения — `СГРУППИРОВАТЬ ПО <Поле>`;
   отбор строками по перечислению невозможен, планируй проверку через группировку.
13. Переводы строк и табуляция в тексте запроса разрешены — запрос можно писать в несколько строк.

Пример:
- Вопрос: «продажи по контрагенту ЭКСПРЕСС ОФИС за 18.09.2026»
- Действия:
  1) `execute_select`: `ВЫБРАТЬ РАЗРЕШЕННЫЕ ПЕРВЫЕ 5 Наименование, ИНН ИЗ Справочник.Контрагенты ГДЕ Наименование ПОДОБНО "%ЭКСПРЕСС ОФИС%"` → точное совпадение «ЭКСПРЕСС ОФИС», ИНН 7707...
  2) `validate_query`: `ВЫБРАТЬ РАЗРЕШЕННЫЕ ПЕРВЫЕ 1 Номер, Дата, СуммаДокумента ИЗ Документ.РеализацияТоваровУслуг ГДЕ Контрагент.ИНН = "7707..." И Дата >= ДАТАВРЕМЯ(2026,9,18) И Дата < ДАТАВРЕМЯ(2026,9,19)`
  3) `execute_select` тем же текстом без `ПЕРВЫЕ 1`.
  НЕЛЬЗЯ: `ГДЕ Контрагент = "ЭКСПРЕСС ОФИС"` (пусто без ошибки), повторный поиск контрагента.
