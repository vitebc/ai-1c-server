# Проверка сквозной нумерации счетов-фактур

## Цель

Для диапазона дат, названного пользователем в вопросе (например, «с 01.09 по 30.09»,
«за 18.09», «за прошлый месяц»), проверить, что номера выданных счетов-фактор идут
подряд без пропусков. В отчёт выводить **только пары** — предыдущий выставленный номер
и следующий выставленный номер, между которыми пропущен хотя бы один номер.

## Шаг 0. Разведка метаданных (не больше 3 вызовов)

Объект известен: `СчетаФактурыВыданные` (в базе это либо документ, либо справочник/
регистр — уточнить через `list_metadata_objects`, какое именно имя с префиксом:
`Документ.СчетаФактурыВыданные` / `Справочник.СчетаФактурыВыданные` и т.п.).

Затем `get_metadata_structure` для этого объекта и убедиться, что есть:
- реквизит даты выставления — «Дата документа» (тип `Дата` или `ДатаВремя`);
- реквизит номера — тип обычно `Строка`, записанный как число (например, `"15"`,
  `"000000015"`). Имя реквизита НЕ выдумывать: взять фактическое из структуры
  (часто `Номер` или `НомерСчетаФактуры`).

Если номера в базе не всегда числовые (есть буквы/прочее) — уточнить у пользователя,
что считать проверяемыми номерами. Дальнейший текст использует имена `ДатаДокумента`
и `Номер`; при реальной проверке подставить фактические имена из структуры.

## Шаг 1. Определить период

Период пользователь называет в вопросе. Преобразовать в две границы:
- «за 18.09.2026» / «за 18.09» → `ДатаДокумента >= ДАТА(2026,9,18) И ДатаДокумента < ДАТА(2026,9,19)`;
- «с 01.09 по 30.09» → `ДатаДокумента >= ДАТА(<Г>,9,1) И ДатаДокумента < ДАТА(<Г>,10,1)`;
- «за прошлый месяц» / «за квартал» — перевести в конкретные даты по текущей дате.

Даты в запросе — ТОЛЬКО `ДАТА(ГГГГ,М,Д)` / `ДАТАВРЕМЯ(ГГГГ,М,Д)`. Строковые даты
(`ДАТА('20260918')`) запрещены. Если пользователь не назвал период и он не выводится
из контекста — спросить один раз: «За какой период проверить?». Не угадывать.

## Шаг 2. Выбрать номера за период

Запрос (имена полей подставить по факту из структуры):


ВЫБРАТЬ РАЗРЕШЕННЫЕ
    Номер,
    ЧИСЛО(Номер) КАК НомерЧислом
ИЗ Документ.СчетаФактурыВыданные
ГДЕ ДатаДокумента >= ДАТА(<Г>,<М>,<Д1>)
  И ДатаДокумента <  ДАТА(<Г2>,<М2>,<Д2>)
УПОРЯДОЧИТЬ ПО НомерЧислом ВОЗР

Требования к синтаксису (нарушение = ошибка 1С):
- Запрос начинается с `ВЫБРАТЬ РАЗРЕШЕННЫЕ`.
- `ПЕРВЫЕ` — только сразу после `ВЫБРАТЬ`, здесь не нужен.
- Подсчёт строк (если понадобится) — `СУММА(1) КАК КЗ`, НЕ `СЧЁТЧИК`/`ПОДСЧИТАТЬ`.
- Группировка — `СГРУППИРОВАТЬ ПО` с буквой «С».
- Пустое поле — `ЕСТЬ NULL`, не `ЕСТЬ НЕОПРЕДЕЛЕНО`.
- Параметры `&` в `execute_select` не поддерживаются — только литералы.

Обязательно: сначала `validate_query` тем же текстом, но с `ПЕРВЫЕ 1` сразу после
`РАЗРЕШЕННЫЕ`, и только при успешной проверке — полный `execute_select`.

Если `Номер` в базе не всегда числовой (есть буквы/прочее) — уточнить у пользователя:
проверяем только строки, которые целиком состоят из цифр. В таком случае добавить в
отбор условие «номер начинается с цифры» через `НАЧАЛОСТРОКИ(Номер, "0")` и т.п. по
факту данных (первые 20–30 значений за период посмотреть глазами).

## Шаг 3. Найти пропуски (в памяти, без SQL-функций)

Работаем со строками предыдущего ответа в памяти:

1. Пройти по отсортированному списку `НомерЧислом` сверху вниз.
2. Для каждой пары соседних значений `(N[i-1], N[i])`:
   - если `N[i] = N[i-1] + 1` — без пропуска, переходить дальше;
   - если `N[i] > N[i-1] + 1` — **пропуск**: в отчёт добавить строку с парой
     «предыдущий номер = N[i-1], следующий номер = N[i], пропущено = N[i] − N[i-1] − 1»,
     и перечислить сами пропущенные номера.
3. Дубликаты (одинаковый номер дважды) — отдельная ситуация; если встретились,
   упомянуть в отчёте строкой «дубликат: номер X встречается K раз», но в основную
   таблицу пропусков их НЕ включать.

Если список пуст — сообщить, что за период счетов-фактур нет.
Если список из одного элемента — пропуска по определению невозможны, сообщить об этом.

## Шаг 4. Отчёт (markdown)

Заголовок: `Проверка сквозной нумерации счетов-фактур за <период>`.

Строки: всего N счетов, минимальный номер X, максимальный номер Y, ожидаемое количество
номеров в диапазоне = Y − X + 1, фактически выставлено = N.

Если пропусков нет — одна строка: «Пропусков не обнаружено».

Если пропуски есть — таблица:

| Предыдущий номер | Следующий номер | Пропущено номеров |
|------------------|-----------------|-------------------|
| 14               | 17              | 2 (15, 16)        |
| 30               | 35              | 4 (31, 32, 33, 34)|

В колонке «Пропущено номеров» перечислить сами пропущенные номера, если их ≤ 5;
если больше — только количество.

## Чего не делать

- Не выдумывать имена документов/реквизитов: сначала `list_metadata_objects` и
  `get_metadata_structure`.
- Не писать строковые даты (`ДАТА('20260918')`) — только `ДАТА(ГГГГ,М,Д)`.
- Не использовать `СЧЁТЧИК(*)` / `ПОДСЧИТАТЬ(1)` — только `СУММА(1) КАК КЗ`.
- Не запускать полный `execute_select` без успешного `validate_query`.
- Не искать пропуски через SQL-подобные конструкции (`LEAD`, `LAG`) — 1С их не знает;
  всё делается в памяти над строками предыдущего ответа.
- Не угадывать период: если пользователь его не назвал явно и он не выводится из
  контекста — спросить один раз, а не брать «сегодня» по умолчанию.

## Пример

Вопрос: «Проверь счета-фактуры с 01.09.2026 по 30.09.2026 на сквозную нумерацию».

Действия:
1. `list_metadata_objects` → подтверждено, что объект называется
   `Документ.СчетаФактурыВыданные`.
2. `get_metadata_structure` для него → реквизиты `ДатаДокумента` (Дата), `Номер` (Строка).
3. `validate_query`:
   

   ВЫБРАТЬ РАЗРЕШЕННЫЕ ПЕРВЫЕ 1 Номер, ЧИСЛО(Номер) КАК НомерЧислом
   ИЗ Документ.СчетаФактурыВыданные
   ГДЕ ДатаДокумента >= ДАТА(2026,9,1) И ДатаДокумента < ДАТА(2026,10,1)
   УПОРЯДОЧИТЬ ПО НомерЧислом ВОЗР
   
4. `execute_select` тем же текстом без `ПЕРВЫЕ 1`.
5. В памяти: [3, 4, 5, 7, 8, 9, 12] → пропуски: (5→7, пропущен 6), (9→12, пропущены 10, 11).
6. Отчёт:

   Проверка сквозной нумерации счетов-фактур за 01.09.2026 – 30.09.2026
   Всего 7 счетов, мин 3, макс 12, ожидаемо 10, фактически 7.

   | Предыдущий номер | Следующий номер | Пропущено номеров |
   |------------------|-----------------|-------------------|
   | 5                | 7               | 1 (6)             |
   | 9                | 12              | 2 (10, 11)        |

Что нужно сверить с живой базой перед использованием:
Префикс объекта: Документ.СчетаФактурыВыданные — допущение; проверить через

list_metadata_objects, что это именно документ (а не справочник/регистр).
Имя реквизита даты «Дата документа» в структуре (фактическое имя может быть

ДатаДокумента, Дата или другое) — через get_metadata_structure.
Имя и тип реквизита номера (фактически Номер / НомерСчетаФактуры; тип Строка


  или Число) — через get_metadata_structure. Если тип Число, убрать ЧИСЛО(Номер)
  из запроса и сортировать напрямую по полю.
