## Назначение

Найти все вхождения произвольной подстроки (слово, символ, фрагмент кода) в коде 1С по всем доступным выгрузкам: конфигурации и расширения. Работает только с **текстовым** поиском — это `search_code` каждого MCP-сервера `search-*`.

## Доступные серверы (выгрузки)

| Сервер | Что индексирует | Инструмент |
|---|---|---|
| `search-erp` | ERP | `search-erp__search_code` |
| `search-upp` | УПП | `search-upp__search_code` |
| `search-ka-market` | КА Маркет | `search-ka-market__search_code` |
| `search-ka-rs` | КА РС | `search-ka-rs__search_code` |
| `search-ka-td` | КА ТД | `search-ka-td__search_code` |
| `search-ka-update` | КА Update | `search-ka-update__search_code` |
| `search-obrabotki` | Обработки | `search-obrabotki__search_code` |

## Порядок действий

1. **Извлеки подстроку** из запроса пользователя (то, что ищем по тексту: `price`, `СуммаНДС`, `Отчет`).

2. **Определи набор серверов:**
   - Пользователь явно назвал базу/выгрузку (ERP, УПП, КА Маркет, обработки и т.п.) → ищи только там.
   - Пользователь **не указал**, в какой базе искать → **спроси**: «В каких выгрузках искать? Доступны: ERP, УПП, КА Маркет, КА РС, КА ТД, КА Update, Обработки. Или — во всех сразу?» Жди ответа, не запускай поиск молча по всем.

3. **Выполни `search_code`** в каждом выбранном сервере с одной и той же подстрокой:
   - Вызовы независимые → делай их параллельно (в одном блоке) для всех выбранных серверов.
   - Аргумент запроса — сама подстрока, как её дал пользователь (без искажений).

4. **Собери итог** в виде простого списка по всем базам. Для каждого совпадения выведи строку формата: 
 ```
<база> :: <полное имя файла> : <строка> : <фрагмент кода>
 ```
Сгруппируй по базе (по одному разделу на базу). Базы, где совпадений нет — отметь «не найдено».

5. Если в какой-то базе много совпадений и ответ раздувается — выведи первые N + укажи общее число найденных в этой базе; не обрезай молча без пометки.

## Формат ответа
 ```
Найдено по подстроке "price":
ERP (search-erp) — 3 совпадения:
  erp :: Документы/СчетаФактуры/Модуль.bsl : 128 : Цена = price * Кол-во;
  ...
УПП (search-upp) — не найдено
КА Маркет (search-ka-market) — 5 совпадений:
Обработки (search-obrabotki) — 5 совпадений:
обработки :: /ТП601 КА ТД/С823_1_ЗагрузкаДанныхИзКАМПвКАТД/Модуль.bsl : 108 : Цена = price * Кол-во;
  ...
 ```
## Чего НЕ делать

- Не использовать `find_references` / `find_symbol` / `semantic_find` для этого сценария — они ищут *символ* (имя процедуры/функции), а не произвольную подстроку. Для «любых вхождений price» — только `search_code`.
- Не запускать поиск по всем серверам, если пользователь не подтвердил — сначала уточни набор баз.
- Не выдумывать имена файлов/строк — выдавай ровно то, что вернул `search_code`.

## Пример

Пользователь: «найди где в коде используется price»
→ Подстрока: `price`. База не указана → спросить, в каких выгрузках искать.
Пользователь: «во всех»
→ Параллельно: `search-erp__search_code(query="price")`, `search-upp__search_code(query="price")`, … по всем 7 серверам.
→ Ответ: список `<база> :: <файл> : <строка> : <фрагмент>` по каждой базе.
 ```
**Проверка перед использованием:
**Имена тулзов сверены с живым list_registry — все 7 search-*__search_code присутствуют.

Уточни у пользователя, какой аргумент принимает search_code (я назвал его query) — если в схеме он называется иначе (например pattern/text), поправь пример вызова; сам список тулзов корректен.
