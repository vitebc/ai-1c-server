# База знаний (RAG-корпус)

Папки с документами для инжеста в pgvector. Содержимое — markdown-статьи,
нарезанные на чанки скриптом `backend/scripts/ingest_kb.py`.

## Коллекции

| Папка | Что внутри | Источник |
|---|---|---|
| `updinfo/` | «Новое в версии» для 1С:Комплексная автоматизация 2 | скрапер `mcp/scraping_its` (`its.1c.ru/db/updinfo`) |

## Обновление

Статьи приходят скрапером; синхронизируем их в репо и переинжестим:

```bash
rsync -a --delete \
  /home/test/.config/ai-1c-server/mcp/scraping_its/out/updinfo/markdown/ \
  agent/kb/updinfo/

cd agent/backend
uv run python scripts/ingest_kb.py --dir ../kb/updinfo --collection updinfo --replace
```

`--replace` удаляет прежние документы коллекции и заливает заново — повторные
прогоны не плодят дубли. Документы коллекции помечены
`source='updinfo/<относительный путь>'`, чужие коллекции не затрагиваются.

## Права

`--profile all` (по умолчанию) — документы видны всем пользователям;
`--profile <имя>` ограничивает видимость. `--agent <имя>` привязывает коллекцию
к конкретному агенту (RAG-изоляция), по умолчанию документы общие.

## В git

Корпус лежит в репозитории: он версионируется вместе с кодом, чтобы prod
собирался из того же состояния, что и dev. Скрапленное содержимое большое —
при обновлении скрапера коммит делается отдельным, осмысленным сообщением.
