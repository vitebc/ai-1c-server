## Сервисные возможности и настройки интеграции
### Интеграция с торговой площадкой Яндекс Маркет. Авторизация пользователей на торговой площадке

Торговая площадка Яндекс
Маркет с октября 2024 года переходит на новый способ авторизации при
использовании методов API: ранее для авторизации использовался стандарт OAuth
2.0, теперь Яндекс Маркет использует авторизацию на API-Key. Выданные ключи по
формату OAuth 2.0 будут работать до конца истечения срока действия.

В описании
изменений интеграции с торговой площадкой используются следующие термины:

*Аккаунт* – учетная запись пользователя
сервисов Яндекс (Яндекс\_ID). В контексте Яндекс Маркета - аккаунт владельца
бизнеса, к которому привязаны кабинеты Яндекс Маркета.

*Кабинет* — центр управления бизнесом на
Маркете. Он позволяет управлять продажами, подключать новые модели, управлять
доступом сотрудников. Каждый кабинет может принадлежать  только одному аккаунту, но к одному аккаунту
может быть привязано много кабинетов.

*Магазин* – магазин на Маркете. Каждый
магазин может принадлежать только одному кабинету

Для настройки
интеграции с торговой площадкой прежде всего нужно добавить кабинет.
Соответствующая команда добавлена в форму Продажи – Сервис
– Продажи на Яндекс Маркет и НСИ и
администрирование – Настройки интеграции – Интеграция с маркетплейсами -
Настройки подключения. Настройки допускают подключения
к нескольким кабинетам.

Для подключения к кабинету
указываются:

■
Наименование кабинета,
которое будет отображаться в информационной базе;

■
Идентификатор кабинета
на торговой площадке;

■ Ключ доступа к методам кабинета.

![](image001.png?_=0002299EE0CA4D1B-v10)

Ключ доступа должен
быть предварительно настроен в личном кабинете на торговой площадке. На форме
приведена краткая и подробная (по ссылке Подробнее)
инструкция. Для удобства ввода информации добавлены кнопки, позволяющие
вставить значения из буфера обмена. Для ключа предусмотрено переключение режима
скрытия (по умолчанию) и отображения символов ключа.

По кнопке Подключить производится сохранение и проверка ключа.
Если сохранение и проверка пройдут успешно – пользователь будет проинформирован
об успешном подключении кабинета. В случае неуспешной авторизации также
выводится сообщение в браузере.

Внимание

В
случае некорректной настройки ключа, не предоставляющей доступа к методам, для
которых настроены фоновые процессы, в журнале регистрации
будут фиксироваться ошибки о нарушении прав доступа.

После подключения
кабинета в информационной базе будет доступен список магазинов, связанных с
этим кабинетом.

![](image003.png?_=0000C370D51C9BB6-v10)

Команда Обновить информацию о магазинах обновляет данные о
магазинах, относящихся к текущему кабинету. Также предусмотрена команда Редактировать данные авторизации, по которой открывается
форма подключения к сервису с авторизационными данными текущего кабинета.
Идентификатор кабинета в этой форме недоступен для редактирования, но есть
возможность изменить наименование кабинета и заменить ключ.

В форме Настройки магазина на закладке Данные
магазина удален реквизит Идентификатор кабинета,
который теперь задается в форме подключения как описано выше. Для реквизита Номер магазина предусмотрена кнопка вставки из буфера.

![](image005.png?_=0000972B3BE2E2AE-v10)

#### Порядок обновления

При первом
подключении после обновления, в случае если в информационной базе ранее был
настроен список магазинов, то он останется, но в новом интерфейсе будет
сгруппирован по кабинетам. При этом в состоянии авторизации кабинета будет
указано, что необходимо обновить авторизационные данные. Продолжить работу по
старому ключу, выпущенного на аккаунт, будет возможно до истечения его срока
действия. По ссылке Требуется обновить авторизационные
данные будет открываться форма подключения к сервису.
