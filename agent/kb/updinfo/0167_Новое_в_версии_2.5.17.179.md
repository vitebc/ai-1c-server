## Сервисные возможности и настройки интеграции
### Интеграция с торговой площадкой Яндекс Маркет. Авторизация пользователей на торговой площадке

Торговая площадка Яндекс
Маркет с октября 2024 года переходит на новый способ авторизации при
использовании методов API: ранее для авторизации использовался стандарт OAuth
2.0, теперь Яндекс Маркет использует авторизацию на API-Key. Выданные ключи по
формату OAuth 2.0 будут работать до конца истечения срока действия.

В описании
изменений интеграции с торговой площадкой используются следующие термины:

*Аккаунт* – учетная запись пользователя
сервисов Яндекс (Яндекс\_ID). В контексте Яндекс Маркета - аккаунт владельца
бизнеса, к которому привязаны кабинеты Яндекс Маркета.

*Кабинет* — центр управления бизнесом на
Маркете. Он позволяет управлять продажами, подключать новые модели, управлять
доступом сотрудников. Каждый кабинет может принадлежать  только одному аккаунту, но к одному аккаунту
может быть привязано много кабинетов.

*Магазин* – магазин на Маркете. Каждый
магазин может принадлежать только одному кабинету

Для настройки
интеграции с торговой площадкой прежде всего нужно добавить кабинет.
Соответствующая команда добавлена в форму Продажи –
Сервис – Продажи на Яндекс Маркет и НСИ и
администрирование – Настройки интеграции – Интеграция с маркетплейсами -
Настройки подключения. Настройки допускают подключения
к нескольким кабинетам.

Для подключения к кабинету
указываются:

■
Наименование кабинета,
которое будет отображаться в информационной базе;

■
Идентификатор кабинета
на торговой площадке;

■ Ключ доступа к методам кабинета.

![](image001.png?_=0002299EE0CA4D1B-v10)

Ключ доступа должен
быть предварительно настроен в личном кабинете на торговой площадке. На форме
приведена краткая и подробная (по ссылке Подробнее)
инструкция. Для удобства ввода информации добавлены кнопки, позволяющие
вставить значения из буфера обмена. Для ключа предусмотрено переключение режима
скрытия (по умолчанию) и отображения символов ключа.

По кнопке Подключить производится сохранение и проверка ключа.
Если сохранение и проверка пройдут успешно – пользователь будет проинформирован
об успешном подключении кабинета. В случае неуспешной авторизации также
выводится сообщение в браузере.

Внимание

В
случае некорректной настройки ключа, не предоставляющей доступа к методам, для
которых настроены фоновые процессы, в журнале регистрации
будут фиксироваться ошибки о нарушении прав доступа.

После подключения
кабинета в информационной базе будет доступен список магазинов, связанных с
этим кабинетом.

![](image003.png?_=0000C370D51C9BB6-v10)

Команда Обновить информацию о магазинах обновляет данные о
магазинах, относящихся к текущему кабинету. Также предусмотрена команда Редактировать данные авторизации, по которой открывается
форма подключения к сервису с авторизационными данными текущего кабинета.
Идентификатор кабинета в этой форме недоступен для редактирования, но есть
возможность изменить наименование кабинета и заменить ключ.

В форме Настройки магазина на закладке Данные
магазина удален реквизит Идентификатор кабинета,
который теперь задается в форме подключения как описано выше. Для реквизита Номер магазина предусмотрена кнопка вставки из буфера.

![](image005.png?_=0000972B3BE2E2AE-v10)

#### Порядок обновления

При первом
подключении после обновления, в случае если в информационной базе ранее был
настроен список магазинов, то он останется, но в новом интерфейсе будет
сгруппирован по кабинетам. При этом в состоянии авторизации кабинета будет
указано, что необходимо обновить авторизационные данные. Продолжить работу по
старому ключу, выпущенного на аккаунт, будет возможно до истечения его срока
действия. По ссылке Требуется обновить авторизационные
данные будет открываться форма подключения к сервису.

### Интеграция с Государственной информационной системой маркировки «Честный знак»
#### Виды маркируемой продукции. Указание сроков начала работы с маркируемой продукцией

Для каждой товарной
группы указываются даты начала обязательной маркировки по сферам деятельности:

●
Производство – с
указанной даты контролируется нанесения кода маркировки на потребительскую
упаковку и подачи в систему маркировки сведения о вводе в оборот.

●
Вывод из оборота –
с указанной даты контролируется передача сведений в систему цифровой маркировки
о выводе из оборота по прочим причинам (не являющимся продажей в розницу).

●
Запрет продаж без марок
– с указанной даты запрещается оборот немаркированных остатков товаров.

●
Розничная продажа – УР
- дата начала уведомительного режима – наступает обязательность сканирования
кодов на кассе при продаже маркированной продукции и передачи сведений о
продажах в систему маркировки с использованием онлайн-касс.

●
Розничная продажа – РР
- дата начала применения разрешительного режима с онлайн проверкой кодов
маркировки при розничных продажах.

●
Розничная продажа – ЛМ ЧЗ
- дата начала обязательной офлайн проверки кодов маркировки при розничных
продажах с использованием локального модуля "Честный знак".

●
Оптовая продажа – ОСУ
- дата обязательности передачи сведений об обороте маркированных товаров с
возможностью применения объемно-сортового учета

●
Оптовая продажа –
поэкземплярно - дата обязательности передачи сведений о кодах маркировки
каждого экземпляра товара

![](image007.png?_=000099FDC3ECFBB7-v10)

Даты
устанавливаются по умолчанию в соответствии с нормативными актами, действующими
на момент выхода версии, но могут быть в случае необходимости изменены
пользователем. Для удобства визуального представления даты ранее текущий
отображаются в таблице словом Действует.

Сроки начала работы
с кодами маркировки влияют на порядок их указания в документах оптовых и
розничных продаж:

■ до
наступления даты обязательной маркировки указание кодов не требуется, в строке
товара пиктограмма маркируемого товара не отображается.

■ после
наступления даты обязательного указания кодов, но до даты запрета продаж без
марок указание кодов является опциональной - можно добавить товар без
считывания кода маркировки. Пиктограмма маркируемой продукции в строке товара
отображается серым цветом (коды маркировки для товаров не указаны),
серо-зеленым (при указании кодов для части экземпляров товаров) или зеленым
(коды указаны для всех товаров).

![](image009.png?_=0000A9245D72E989-v10)

■ после
наступления даты обязательной маркировки (в рознице, как правило, вначале
наступает уведомительный режим) при сканировании штрихкода товара товар
требуется код маркировки, без него добавление товара невозможно. В строке
товара до указания всех кодов маркировки отображается пиктограмма красного
цвета, а при пробитии чека будет выдано предупреждение, что не отсканировано
нужное количество кодов маркировки. В оптовых продажах при попытке сформировать
ЭД будет выдано предупреждение, что требуется указание кодов маркировки.

#### Офлайн проверка для разрешительного режима

Для осуществления
проверок разрешительного режима при розничных продажах (см. Постановлением
Правительства РФ от 21.11.2023 № 1944 в ред. Постановления Правительства РФ от
22.11.2024 № 1606) помимо онлайн-проверки предусмотрено выполнение проверки
офлайн с помощью специального программного обеспечения, разработанного
оператором маркировки "Честный знак", который устанавливается на
компьютер продавца (далее Локальный модуль "Честный знак" или ЛМ ЧЗ).
Локальная проверка требуется в случае невозможности получения идентификатора
онлайн ввиду отсутствия стабильного интернета или неполадок на стороне ГИС МТ.
После наступления даты, оговоренной законодательством, продажа без
осуществления запроса к Локальному модулю «Честный знак» запрещена.

Даты начала
действия локальных проверок указываются в панели настроек НСИ и администрирование – Настройки интеграции - Интеграция с
ИС МП (обувь, одежда, табак…) в графе Розничная
продажа – ЛМ ЧЗ таблицы видов маркируемой продукции. Даты установлены в
соответствии с действующими нормативными актами, но их можно редактировать в
случае необходимости. После наступления указанной даты обязательной локальной
проверки в отсутствие настроенных Локальных модулей при сканировании или
пробитии будет выдаваться ошибка – продать товар будет невозможно.

Для работы с ЛМ ЧЗ
необходимо скачать со страницы <https://честныйзнак.рф/local-module/>  установочный пакет (дистрибутив) и установить
его на компьютере в локальной сети продавца (сервер или компьютер, с которого
будут осуществляться розничные продажи). На этой же странице можно скачать
инструкцию по установке локального модуля. При установке потребуется придумать
задать логин и пароль администратора. В дальнейшем их нужно будет указать при
настройке подключения к локальному модулю. На этапе интеграции и отладки
следует использовать адрес демонстрационного стенда -
https://suz-rsapi.sandbox.crptech.ru. Для корректной работы также нужно
обратить внимание на соответствие разрядности (32 бита / 64 бита) модуля и
остального ПО. После завершения установки модуля настройки выполняются на
стороне информационной базы 1С.

В панели настроек НСИ и администрирование – Настройки интеграции - Интеграция с
ИС МП (обувь, одежда, табак…) по ссылке Настройка
подключения к ЛМ ЧЗ открывается список настроенных подключений к
Локальным модулям "Честный знак". В списке можно настроить новое
подключение по команде Создать.

Настройка
производится отдельно по каждой организации. Обмен между информационной базой и
ЛМ ЧЗ может выполняться На сервере 1С:Предприятие
или На локальном компьютере. В случае обмена на
локальном компьютере, можно указать конкретное Рабочее
место (компьютер с подключаемы торговым оборудованием) к которому будет
применяться эта настройка ЛМ ЧЗ. Рабочие места создаются в списке подключаемого
оборудования. Если рабочее место не указано, то настройка ЛМ ЧЗ будет
применяться ко всем рабочим местам.

При создании новой
настройки предварительно заполняется адрес подключения согласно параметрам
установки Локального модуля «Честный знак» по умолчанию.

![](image011.png?_=0000646B5916C2D0-v10)

По гиперссылке Виды продукции
открывается окно со списком учитываемых товарных групп, поддерживающих
локальную проверку разрешительного режима, по которым будет выполняться
проверка в рамках этой настройки.

После заполнения всех необходимых параметров подключения
запускается процедура определения текущего статуса Локального модуля «Честный
знак». При первой установке подключения выполняется ряд действий по первичной
настройке и формированию локальной базы кодов маркировки для корректной работы.
До завершения настройки коды маркировки не могут быть проверены через такой
Локальный модуль "Честный знак". Процесс настройки занимает
определенное время в зависимости от производительности машины с установленным
модулем, скорости загрузки по сети и загруженности ГИС МТ.

В случае внесения изменения в список учитываемых видов
продукции или количества дней выгрузки карточек необходимо повторно передать
данные в Локальный модуль «Честный знак» в карточке настройки подключения ЛМ
"Честный знак" по ссылке Синхронизировать виды
продукции.

После успешной синхронизации данных из ЛМ ЧЗ в карточке
подключения отображается дата последней синхронизации с центральной базой.

![](image013.png?_=000067B5EE61E038-v10)

В случае ошибок синхронизации или указании некорректных
настроек отображается причина проблемы.

По кнопке Изменить (пиктограмма в виде карандаша) рядом с
полем Пароль можно изменить стандартный пароль
Администратора, заданный при установке Локального модуля «Честный знак». Новый
пароль при установке должен отвечать внутренним условиям проверки на сложность.

![](image015.png?_=00009DEE77659E31-v10)

При выполнении запроса разрешительного режима из документов
продажи на локально установленных модулях ввиду длительности выполнения такой
операции отображается прогресс выполнения.

Информация о выполненных проверках сохраняется в журнале
проверки в информационно базе в регистре сведений.

Посмотреть Операции проверки КМ
по конкретной продаже можно на закладке Проверка КМ
формы Фискальная операция, которая открывается по
ссылке Пробит чек №… из документа, которым
отражена розничная продажа.

![](image017.png?_=0000D7337D78A8BB-v10)

В форме Операции проверки КМ на
закладке Основное отражается результат проверки.

![](image019.png?_=000192C7C8B0A2CF-v10)

На закладке Разрешительный режим
можно посмотреть текст запроса и тест ответа разрешения. В случае возникновения
таймаута онлайн разрешительного режима будет отправлен запрос на установленные
Локальные модули «Честный знак» и сохранен результат запроса с указанием
локального модуля.

![](image021.png?_=0001EDAACD9B093B-v10)

Посмотреть весь журнал операций проверки кодов маркировки, а
также настроить срок хранения записей можно в разделе НСИ
и администрирование – Администрирование – РМК и оборудование.
