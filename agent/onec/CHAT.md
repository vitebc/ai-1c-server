# Чат-клиент

В расширении `A1C_Инструменты` четыре обработки чата. V1 — форк ИИконы под бэкенд
агента, V2/V3 — прямой чат с сервером OpenCode без бэкенда агента.

| | V1 `a1c_Чат` | V2 `a1c_ЧатOpenCodeV2` | V3 `a1c_ЧатOpenCodeV3` |
|---|---|---|---|
| Куда ходит | бэкенд агента `POST /chat` (SSE) | OpenCode API v2 | OpenCode API v2 |
| Интерфейс | поля формы + HTML-поле под ответ | HTML-поле `ОтветHTML` | одна HTML-страница: шапка, лента, ввод, агенты, статус, вопрос |
| Отрисовка | сервер собирает HTML ответа | HTML пересобирается целиком на каждом шаге опроса | страница рисуется **один раз**, дальше 1С зовёт её JS-функции |
| Ответ на вопрос модели | — | одним текстом на все ключи | по каждому полю, отправка одной кнопкой |
| Где состояние | `ОтветHTML` + `ИсторияДиалога` | то же | реквизиты формы + клиентские переменные; страница состояния не хранит |

Актуальная — **V3**. V2 оставлена как предыдущая версия (перерисовка всей страницы
на каждом опросе). V1 — отдельный контур под БСП-бэкенд (`agent/`), ниже про него.

## V1: что дёрнули

Форма `a1c_Чат.Форма` («ИИ ассистент») — форк `КИИ_ТестИИ` из [andromanpro/1c-ai-connector](https://github.com/andromanpro/1c-ai-connector) (MIT). BSL на стриминг не способен — поэтому гибрид: BSL + JS.

- **Вёрстка:** `Pages` с вкладками `Диалог` / `Вложения`, `HTMLDocumentField ОтветHTML` на весь VerticalStretch, группа `ГруппаКоманды` с `Отправить` (DefaultButton), `ВыполнятьВФоне` (Switcher), `РазмерКонтекста` (spin), `Агент` (дропдаун из `GET /agents`, дефолт Ассистент; выбор скила убран — всегда авто на бэкенде), `Очистить`/`ПрикрепитьФайлы`, баннер `ПредупреждениеБазы` (декорация, скрыта по умолчанию).
- **Рендер истории на сервере:** `ШаблонДиалога` (HTML+CSS пузырьки `message user/assistant/error`, `.role`, `.meta`, таблицы/код/цитаты) + `a1c_МаркдаунПарсер` (форк `КИИ_МаркдаунПарсерКлиентСервер`, MIT) с `ПреобразоватьВHTML()` и XSS-защитой `ЭкранироватьHTML()`. Пустое состояние `История диалога пуста`.
- **Мета-строка:** `⚡ Токены: X | ⏱ Время: Yс | ⚒ Модель: Z` под каждым ответом
  (берётся из `done`: `total_tokens`/`elapsed_s`/`model`; нули — провайдер не вернул `usage`).
- **Настройки:** `ХранилищеОбщихНастроек` (Эксперт/ВыполнятьВФоне/РазмерКонтекста), загрузка/сохранение в `ПриСозданииНаСервере`/`ПередЗакрытием`.
- **Вложения:** `ТаблицаВложений` (Отправлять, Направление, Имя, MIME, Размер, Адрес во временном хранилище), drag-and-drop `AsFileRef`, `ПрикрепитьФайлы` через `ФайловаяСистемаКлиент`, `MIMEПоИмениФайла`, `КонтентВложения` для мультимодала.
- **Фон:** `ДлительныеОперации` — если `ВыполнятьВФоне`, BSL не виснет: `ФоновыеЗадания.Выполнить(a1c_ЧатФоновыйВызов)` + ожидание.

## V1: как устроено

- Модуль формы: `АдресБэкенда` (дефолт `http://localhost:8000`) + `%USER_NAME%` = `ИмяПользователя()` (спрашивающий). `ОбновитьОтображениеОтвета()` генерит `ОтветHTML` через `ПолучитьМакет("ШаблонДиалога")` → `[MESSAGES]` → `СформироватьHTMLСообщения()` → `a1c_МаркдаунПарсер`.
- Отправка: `Отправить` → `ВызватьБэкендЧат()` — BSL делает `HTTPСоединение`+`HTTPЗапрос` `POST /chat {message, user_id, base_name, base_url, session_id?, attachments, context_size, agent}` и парсит SSE (`answer`/`tool`/`done`) на сервере (`ИзвлечьОтветИзSSE`, мета `session_id/agent/skill/model/elapsed_s/total_tokens` — `ИзвлечьМетаИзSSE`). `base_name` = `a1c_ЧатФоновый.ИмяИнформационнойБазы()`, `base_url` = `a1c_ЧатФоновый.АдресПубликацииБазы()` (файловая ИБ — пусто). Тело ошибки бэкенда (первые 300 символов) прикладывается к тексту исключения — эхо `400` про базу видно в чате. Поле `skill` форма не шлёт (авто-матчинг на бэкенде). Если `ВыполнятьВФоне` — уходит в `a1c_ЧатФоновый.ВыполнитьЗапрос` (те же поля + фоновая схема).
- Проверка при старте: `ПроверитьДоступностьБазы()` дергает `GET /tools?base_name=&base_url=` (параметры URL-кодируются `КодироватьПараметрURL`, пустой ответ/ноль тулзов — тоже ошибка) и при неуспехе показывает некритичный баннер `ПредупреждениеБазы` («Агент недоступен для этой базы (адрес): причина»), форма открывается в любом случае.
- JS в `HTMLЧат` оставлен как fallback для старого SSE, но основной путь — BSL `ОтветHTML` через `ШаблонДиалога`. Открытие: **Все функции** → Обработки → `a1c_Чат`.

## V1: контур запуска

### Основной — бэкенд на Linux (VPS/сервер)

```bash
cp .env.example .env          # LLM_*, ONEC_USERNAME/PASSWORD (+ONEC_BASES), MCP_ONEC_URL=http://<1С-хост>/base
docker compose up -d postgres backend   # :8000, миграции сами
docker compose logs -f backend
# прокси рядом на Linux (8001) — только для штатного пути без base_url:
pip install -r /path/to/1c_mcp/src/py_server/requirements.txt
python -m src.py_server http --port 8001 --onec-url http://<iis>/ka2test --onec-username agent --onec-password ...
# .env: ONEC_MODE=live  ONEC_MCP_URL=http://localhost:8001  # внутри compose http://mcp-proxy:8000
```

Основной путь мультибазы прокси НЕ требует: бэкенд ходит в `{base_url}/hs/mcp/rpc`
напрямую (форма шлёт `base_url`, исключения — через `ONEC_BASES`).

Требует сети Linux → Windows-VM (VPN/Tailscale/проброс IIS/SSH-туннель). Если сети нет — fallback ниже. В 1С поле «Бэкенд» → `http://<linux-хост>:8000`.

### Fallback — всё на Windows (без сети)

`docker compose up -d postgres` в Docker Desktop + `uv run uvicorn` и прокси на той же машине. «Бэкенд» → `http://localhost:8000`.

`ONEC_MODE`: `mock`/`live`. Смоук: `uv run python scripts/smoke_tools.py --live` (и `--replay`).

## V3 — чат с OpenCode (одна HTML-страница)

`a1c_ЧатOpenCodeV3` ходит напрямую в сервер OpenCode (API v2), без бэкенда агента
и без БСП. Вся сеть — в общем модуле `a1c_ЧатOpenCodeФоновый`
(Basic `opencode`/`123` в конструкторе `HTTPСоединение`, адрес по умолчанию
`http://192.168.60.39:4040`, таймаут запроса 300 с, у опроса — 15 с).

```
Форма
├── ПанельHTML            — поле HTML-документа на весь экран; страница рисуется один раз
├── АдресБэкенда, Агент   — реквизиты + ХранилищеОбщихНастроек
├── ИдентификаторСессии   — сессия OpenCode (пусто = новая при первом промпте)
├── Агенты                — ValueTable: Идентификатор, Имя (GET /api/agent)
├── ИсторияДиалога        — ValueTable: Роль, Текст, Метаинформация
└── ТекущийИдВопроса      — id формы-вопроса, которую сейчас показываем
```

Страница собирается из трёх макетов (все — чистый ASCII, кириллицу добавляет BSL):

| Макет | Что внутри |
|---|---|
| `КаркасСтраницы` | скелет с `{{STYLES}}`, `{{SCRIPT}}`, `{{HEADER}}`, `{{FEED}}`, `{{COMPOSER}}` |
| `СтилиСтраницы` | палитра V1/V2: белый фон, синие `user`, зелёные `assistant`, красные `error`, Consolas для кода, `.opt.on` для выбранного варианта |
| `СкриптСтраницы` | `upsertMessage`, `setMeta`, `showQuestion`/`hideQuestion`, `selectOption`, `setValue`, `setStatus`, `setBusy`, `setHeader`, `clearFeed`, `clearPrompt`, `focusPrompt`, `getValue`, `onPromptKey`, `onQuestionKey` |

### Почему страница не перерисовывается

`ПанельHTML = СформироватьСтраницу(...)` вызывается **один раз** в `ПриСозданииНаСервере`.
Дальше 1С не отдаёт HTML заново, а зовёт функции страницы через
`Элементы.ПанельHTML.Документ.defaultView` (в старом движке — `parentWindow`,
см. `ПолучитьОкноСтраницы()`) и передаёт готовый HTML одного блока:
сообщение — `upsertMessage(id, html)`, мета — `setMeta(id, text)`, карточка вопроса —
`showQuestion(html)`. Поэтому прокрутка и уже нарисованные сообщения не сбрасываются,
когда ответ модели дописывается. Полная перерисовка (`ПерерисоватьСтраницу()`) —
только аварийный путь внутри `Исключение`, с восстановлением статуса и вопроса.

### Обратный канал — только ссылки `#act:`

В странице нет кнопок с обработчиками: всё, что нажимается, — `<a href="#act:...">`.
`ПанельHTMLПриНажатии` ищет в `Href` подстроку `#act:` (платформа отдаёт Href
абсолютным и раскодированным), ставит `СтандартнаяОбработка = Ложь` (иначе поле
прыгнет по якорю) и разбирает команду:

| Команда | Что делает |
|---|---|
| `send` | отправить текст из `#prompt` (пусто — `ПоказатьВводСтроки`) |
| `stop` | `POST /api/session/{sid}/interrupt`, опрос останавливает клиент |
| `clear` | очистить ленту, вопрос, поле ввода и сессию на сервере |
| `backend` | сменить адрес сервера (только пользователь-разработчик) |
| `agent\|<id>` | сменить агента (сессия сбрасывается: агент задаётся при её создании) |
| `opt\|<поле>\|<вариант>` | выбрать вариант ответа (ничего не отправляет) |
| `answer` | отправить ответы всех полей одним `reply` |

### Готовность страницы

`ДокументСформирован` приходит не во всех движках и не всегда, поэтому его дублирует
сторож `ПроверитьГотовностьСтраницы`: однократный таймер раз в секунду, до 30 попыток,
перевзвод в конце, проверка `Документ.getElementById("prompt") <> Неопределено`.
Пока `СтраницаГотова = Ложь`, все обёртки вызова JS молчат — иначе каждая попытка
уходила бы в `Исключение` и перерисовывала страницу.

### Ход и опрос

1. `НачатьХодНаСервере` → `a1c_ЧатOpenCodeФоновый.ОтправитьПромптБезОжидания`:
   первая реплика создаёт сессию (`POST /api/session` с `title`, `agent` и моделью —
   первый non-`opencode` провайдер из `GET /api/provider`), дальше —
   `POST /api/session/{sid}/prompt {text}`.
2. `prompt` возвращает только квитанцию с `time.created` — это `ВремяНачала`.
3. Клиент опрашивает раз в 0,5 с: `GET /api/session/{sid}/message?order=desc&limit=50`
   (desc, берём `assistant` с `time.created >= ВремяНачала`, склеиваем текстовые части).
4. Ход завершён по сообщению `idle` с `time.created >= ВремяНачала` **и** при отсутствии
   ожидающих форм: пока форма не отвечена, `idle` не появляется.
5. Страховка: 10 минут без завершения — опрос прекращается, кнопка «Отправить»
   разблокируется, в статус уходит честный текст.

### Вопрос модели: несколько полей, одна отправка

`GET /api/session/{sid}/form` отдаёт формы; карточка рисуется по полям
(`Поле.key`, `title`, `description`, `Варианты`):

- у каждого поля свои варианты (`#act:opt|i|j`) и своё поле свободного ответа
  (`qfree_i`), выбранный вариант подсвечивается классом `.opt.on`;
- клик по варианту **ничего не отправляет** — ответ запоминается в `ОтветыНаВопрос`
  (`Соответствие` «ключ поля → текст»), статус показывает «Осталось ответить: N»;
- кнопка «Ответить» одна: собирает ответы всех полей (свой текст перекрывает вариант)
  и отправляет **один** `POST .../form/{fid}/reply {"answer": {q0: ..., q1: ...}}`;
- если хоть одно поле пустое, отправки нет: форма останется pending и ход зависнет;
- `ОтвеченныйИдВопроса` помнит уже отвеченную форму — пока сервер её не убрал,
  карточка повторно не показывается, но опрос не останавливается;
- резервный путь без DOM — по одному полю через `ПоказатьВводСтроки`, отправка всё равно одна.

### Агенты, настройки, версия

- Агенты — `GET /api/agent`, только `mode = "primary"` и не `hidden`.
- Адрес и агент сохраняются в `ХранилищеОбщихНастроек`, ключ
  `a1c_ЧатOpenCodeV3_НастройкиФормы` (`Структура`: `АдресБэкенда`, `Агент`).
- Адрес сервера меняет только пользователь, для которого `ЭтоРазработчик()` истинно
  (сейчас это жёстко заданное имя); остальным адрес показывается, но не редактируется.
- В шапке справа — короткий хеш сборки: `ВерсияСборки()` читает
  `Обработки.a1c_ИнструментДерево.ВерсияРасширения()` (`ExtVersion.txt`,
  пишется `bump_ext_version.py`). По нему видно, загрузилось ли расширение.

### Ответы и разметка

Текст сообщения проходит `ОбработатьТекстСообщения`: полный HTML-документ — как есть,
JSON — в `<pre>`, HTML-фрагмент — как есть, иначе markdown → `a1c_МаркдаунПарсер.ПреобразоватьВHTML`.
Пользовательский текст всегда экранируется (`ЭкранироватьHTML`).
